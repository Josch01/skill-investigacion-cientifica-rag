# Runtime Profile: MULTI_PROVIDER_COUNCIL

## Purpose

Use provider diversity where it can reduce correlated reasoning errors without turning disagreement into voting.

## Recommended allocation

A typical R3 task may use:

- Provider A: Research Architect / Scientific Lead
- Provider B: bounded Theory/Proof/Numerical worker
- Provider A or C: Scientific Auditor
- a different context/provider when possible: Independent Reviewer

This is only a recommendation; role authority remains canonical.

## Rules

- use `protocols/MULTI_AGENT_HANDOFF.md` for real handoffs;
- preserve task/mission hashes;
- apply Context Firewall;
- disagreement opens a dispute;
- provider diversity does not waive proof/certification gates;
- majority vote is forbidden.
